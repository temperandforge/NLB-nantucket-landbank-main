# Absorbing nlb-design into the Sanity and Next.js site

Status: draft for review. Source: `/Users/jtf/Developer/nlb-design`, a standalone Next.js 16 and
Tailwind 4 project that builds the Figma designs with hard-coded content (no CMS). It is the newer,
Figma-faithful implementation; this repo's blocks so far were ported from the WordPress theme
([slice 1 spec](2026-10-07-wp-blocks-migration-design.md)).

## Decision

Port `nlb-design`'s components into this repo as Sanity-driven blocks, then retire it. Where it
overlaps a theme-ported block, `nlb-design`'s visuals win. No git history is carried over, and the
old folder is not touched or deleted. Its `node_modules`, `.next` and `.claude/worktrees` are
never copied.

This supersedes slice 1's "port the theme exactly" rule for the overlapping blocks only.

## Goal

An editor builds every page in `nlb-design` from Studio, and the site renders them as `nlb-design`
does. Nothing in `nlb-design` needs to be consulted afterwards.

## Two phases, one spec

Each phase gets its own implementation plan. Phase B starts after Phase A is built.

### Phase A: static blocks and shared UI

**Shared UI** in `frontend/components/ui/`: `Tag`, `Button` (primary, secondary, ghost), `LinkButton`,
`IconButton`, and the link row (`link-item`). Component CSS from `css/components/*.css` is merged
into `frontend/css/` following this repo's conventions (tokens named after Figma variables).

**New blocks**

| Block | From | Fields |
|---|---|---|
| `missionStatement` | `MissionStatement` | eyebrow (tag), heading, `links[]` (label, link) |
| `ctaContact` | `CtaContact` | heading, body, button (label, link), desktop and mobile background images |

**Reworked blocks** (existing Sanity types keep their names, so no content migration)

- `basicLeftRightText` takes `BasicLeftRight`'s design: eyebrow and heading on the left, with an
  optional repeater of **buttons** under them (label, link, and a Primary, Secondary or Ghost
  style); the right is rich text. The theme's left-column body text and single button are removed.
  - Rich text offers Normal, H3-H6 and Quote only (H1 and H2 are already removed from
    `blockContent`).
  - Rich text gains an **anchor links** item: a repeater of rows, each with a label, a link and an
    icon, **Link** (arrow) or **Download**. Rows are separated by 16px and styled as `nlb-design`'s
    `link-item`.
- `heroTertiary` takes `HeroTertiary`'s design. `SectionIntro` is the same layout with an H2, so it
  is the existing heading-level option, not a second block.
- `heroImage` takes `HeroQuaternary`'s design (background photo with a light card holding the
  eyebrow and title). They are the same component, so there is no new block.
- `timeline` takes `HistorySlider`'s design. This adds `@splidejs/splide` as a dependency.

**Not ported:** `VideoBand` (the existing `heroVideo` covers it and has a pause control) and
`Footer` (this repo has one).

**Unchanged:** `heroSecondary` (including its light-brown variant), `jumpNavContent`,
`imageCarousel`, `downloadBlock`, `mapTeaser`, `contactForm`.

**Typography is replaced, not added to.** This repo's stepwise `--text-display-*` and
`--text-headline-*` become `nlb-design`'s fluid clamps (plus `--text-headline-2xl`), the
`text-headline-*` utilities carry the serif heading style, and `--tracking-wide` becomes 2px (tags
and eyebrows use it). The slice 1 `text-h1`..`text-h6` utilities are removed and their users moved
to `text-headline-*` by visual size. The footer's `text-headline-base` now shares the heading
style and is flagged for a design check.

**Moved in:** decorative line art, `icon-download.svg`, `icon-arrow-right.svg` and the chevrons into
`frontend/public/`; images and the video it uses only if a block needs them; its `docs/`
(Figma-to-code conventions, typography, token notes) into `docs/`, merged with this repo's
`DECISIONS.md` rather than copied over it. `tokens.css` is reconciled against this repo's: both come
from the same Figma variables, so differences are reported and resolved, not silently overwritten.

### Phase B: data-driven pieces

**Documents** (ids generated by Sanity; none are singletons)

- `article`: title, slug, date, image, `categories[]` (references).
- `event`: title, start and end date-time, location, description, image.
- `staffMember`: name, title, `department` (reference), headshot, order.
- `commissioner`: name, title, start date, headshot, order.
- `faq`: question, answer, `category` (reference).
- Taxonomies, as referenced documents so the client can extend them without a deploy:
  `newsCategory`, `department`, `faqCategory`. The slug is the stable key, the title is the label.

**Cards** in `frontend/components/cards/`: `CardNews`, `CardStaff`, `CardCommissioner`,
`CardProject`. Their types derive from the generated query types. `CardProject` renders the
existing map `project` documents, with property types and resources as its tags, so this repo
keeps a single "project". The theme's separate work-"project" type is not carried over.

**Blocks**

- `newsPreview`: heading, the latest N articles, a call-to-action heading, label and link.
- `eventsPreview`: eyebrow and the upcoming events. "Upcoming" is computed at render from the
  dates, never stored.
- `faqList`: FAQs grouped by category, using `nlb-design`'s accordion button. Native `details`
  semantics or an equivalent accessible disclosure, to be fixed in the plan.
- `peopleGrid`: staff or commissioners, in their hand-set order.
- `projectGrid`: every map project.
- The grids list everything. Filters, pagination and per-item pages stay in slice 3
  ([#11](https://github.com/temperandforge/NLB-nantucket-landbank-main/issues/11)); the blocks
  and their cards replace what was slice 2 ([#10](https://github.com/temperandforge/NLB-nantucket-landbank-main/issues/10))
  except those and the theme blocks that have no `nlb-design` counterpart (`preview-projects`,
  `preview-properties`, `job-openings`), which stay on #10.

## Conventions carried forward

- Only singletons get explicit `_id`s; relationships are `reference` fields; derivable values are
  computed at render.
- Tokens are added per feature, named after Figma variables; an existing token beats raw hex, with
  any discrepancy flagged.
- Figma assets are committed, never hotlinked. Anything rendered must degrade, never throw.
- Every block gets the "Hide this block" setting, and the page builder's insert menu stays sorted
  by title (both are already in place).
- Unbuilt interactive features ship disabled, and every deferred item gets a GitHub issue.
- Seed and migration scripts run through `sanity exec`, are idempotent, state what they overwrite,
  and have a `--dry` mode. The block gallery seed is extended to cover new blocks.

## Known gaps and risks

- `nlb-design` has no archive pages, filters or per-item pages beyond its FAQs page, so none are
  designed here.
- `nlb-design` has open conventions it records itself (`docs/deferred-work.md`): the 12-column grid
  retrofit, the inline-utility versus `@utility` choice, and invalid `--spacing-s1..s8` tokens.
  These are reviewed during the port and the outcome recorded; they are not assumed fixed.
- `nlb-design`'s Next version (16.3.4) is newer than this repo's (16.2.7). Components are checked
  against this repo's installed docs before use.
- Staff departments are a fixed union in `CardStaff`; here they come from `department` documents,
  so the card must not restate their values (rule: derive from generated types).
- The Figma nodes for the anchor-links design (`2668:7765`, `2668:12795`) are not readable through
  the Figma tool. Phase A builds it from `nlb-design`'s `link-item` and the 16px spacing given in
  the request, and verifies it against a screenshot from the user.
- Follow-up issues: design tokens to confirm with the designer
  ([#14](https://github.com/temperandforge/NLB-nantucket-landbank-main/issues/14)) and a visual
  comparison of the reworked blocks against Figma in Presentation
  ([#15](https://github.com/temperandforge/NLB-nantucket-landbank-main/issues/15)).

## Verification

- Per phase: `npm run sanity:typegen`, `npm run type-check`, `npm run lint` in `frontend`;
  `npx tsc --noEmit` in `studio`. Generated files are committed.
- The block gallery seed is extended with every new block, and Phase B adds sample content for the
  new documents. The user reviews it in Studio Presentation (draft only, nothing published).
- Page hierarchy is not touched, so `verifyPageRouting.ts` is not required.
